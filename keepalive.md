# keepalive.sh — защита Always Free сервера Oracle от отключения за простой

Запуск: `sudo bash keepalive.sh` **на самом сервере Oracle** (не на том, где идёт поиск). 492 строки, `bash -n` проходит. Написан заранее, чтобы быть готовым к моменту создания Ampere; работает и на Micro.

---

## 1. Зачем

Oracle может отключить («reclaim») Always Free сервер, если **7 дней подряд все** метрики ниже порога 20%:
- ЦП (95-й процентиль),
- сеть,
- память (проверяется **только на Ampere A1**, у Micro память не проверяется).

Достаточно держать выше 20% **любую одну** метрику. Лёгкие сервисы (например AdGuard Home: ~1–2% ЦП, 50–150 МБ памяти) этого не обеспечивают: на 6 ГБ памяти это около 2% при пороге 20%.

Выводы по обсуждению с Vitalii:
- Для Ampere самый удобный способ — **память**: почти не грузит ЦП, стабильна, одного процесса достаточно. Целевая занятость не 20%, а **около 30%** (запас на то, что Oracle может считать память иначе, чем `free`). Для 6 ГБ это ≈1,8 ГБ, остаток ≈4 ГБ остаётся под AdGuard и остальное.
- Для Micro память не помогает — нужна **лёгкая периодическая нагрузка на ЦП**.

## 2. Что делает скрипт

- Сам определяет тип сервера по архитектуре (`uname -m`): `aarch64/arm64` → режим **mem** (ARM Ampere), иначе → режим **cpu** (AMD Micro). Дополнительно читает форму сервера из метаданных Oracle (`http://169.254.169.254/opc/v2/instance/shape`), только для показа.
- Раз в сутки (и при каждом запуске) **анализирует**, сколько памяти/ЦП используют программы пользователя, и подстраивает размер: программы пользователя всегда в приоритете.
- Если свободной памяти становится мало, сразу отдаёт её обратно (резерв `MEM_RESERVE_PCT=10` %, не меньше `MEM_RESERVE_MIN_MB=300` МБ).
- Работает как служба systemd `keepalive` с автозапуском (переживает перезагрузки).
- Историю хранит на диске (переживает перезапуск службы), статус пишется в `status.json`.
- Удаляется одним пунктом меню, память освобождается.

### Режим «память» (ARM)
Демон занимает блоками по 64 МБ (`CHUNK_MB`) столько оперативной памяти, чтобы общая занятость (программы пользователя + занятое скриптом) была около `MEM_TARGET_PCT` (по умолчанию 30%, допустимо 25–60). Если программы пользователя выросли, демон уменьшает свою долю.

### Режим «ЦП» (AMD Micro)
Целевая доля времени с ЦП выше 20%: `CPU_TARGET_PCT` (по умолчанию 10, допустимо 7–30). Порог Oracle по 95-му процентилю означает, что не менее ~5% времени ЦП должен быть выше 20%. Демон добавляет короткие всплески (`KA_BLOCK=3` шага по минуте = 3 минуты, с самым низким приоритетом, чтобы не замедлять программы пользователя) ровно в таком количестве, чтобы суммарно набрать нужное время; если программы пользователя сами дают нагрузку, всплески реже.

Параметры демона можно переопределить переменными окружения (`KA_TICK=60`, `KA_CHUNK_MB`, `KA_DAY_TICKS=1440`, `KA_BLOCK`, `KA_BUCKET_TICKS=10`) — это нужно для тестов в ускоренном времени.

## 3. Файлы

| Что | Путь |
|---|---|
| служба | `SVC=keepalive`, `/etc/systemd/system/keepalive.service` |
| демон (Python 3, генерируется скриптом) | `/usr/local/sbin/keepalive-daemon.py` |
| настройки | `/etc/keepalive.conf` |
| состояние/статус | `/var/lib/keepalive/state.json`, `/var/lib/keepalive/status.json` |
| журнал | `/var/log/keepalive.log` (ротация при >1 МБ, остаются последние 300 строк) |

`/etc/keepalive.conf`:
```
MODE=auto            # auto (по типу сервера) | mem | cpu | both
MEM_TARGET_PCT=30
MEM_RESERVE_PCT=10
MEM_RESERVE_MIN_MB=300
CPU_TARGET_PCT=10
```

## 4. Меню

1. Установить / переустановить (с анализом сервера): показывает тип сервера, текущую занятость, предлагает целевой процент, останавливает старую службу, пишет конфиг и демон, включает службу.
2. Статус: режим, память всего / ваши программы сейчас (среднее за сутки, пик) / занято скриптом / общая занятость / свободно / резерв; для ЦП — текущая загрузка, идёт ли всплеск, доля времени, когда программы сами держат ЦП выше 20%, число всплесков в сутки; время последнего анализа; предупреждение, если данные устарели (>3 мин); последние 6 строк журнала.
3. Остановить (память освобождается, автозапуск выключен).
4. Запустить.
5. Настройки (только целевой процент; применится при следующем анализе или после перезапуска).
6. Удалить (служба, демон, конфиг, каталог состояния, журнал).
0. Выход.

Требования Vitalii (все выполнены): работает на обоих типах процессоров (определение автоматически), память измеряется ежедневно и размер подстраивается, для Micro то же самое через ЦП.

## 5. Технические заметки

- Демон на Python 3 (`ensure_python` ставит `python3`, если нет). Память занимается блоками `bytearray`, которые закрепляются в оперативной памяти через `mlock` (вызов libc через `ctypes`), чтобы система не вытеснила их в swap и Oracle видел память занятой; если `mlock` не разрешён, выводится предупреждение один раз.
- Тестировался в ускоренном времени с переменными окружения `KA_*` (каталог `ka/` в scratchpad: демон + тест).
- Всплеск ЦП — это `nice -n 19 timeout <3 мин> sh -c "while :; do :; done"` (низший приоритет), чтобы не мешать программам пользователя.
- Для Micro (1 ЦП, ~1 ГБ RAM) на этом же сервере работают TorrServer, qBittorrent, Jackett — keepalive не должен им мешать; поэтому всплески короткие и с минимальным приоритетом.
- Задел на будущее: режим `both` (память + ЦП одновременно) есть в конфиге, но по умолчанию не используется.

## 7. Заметки из обсуждений

- В скобках `[10]` в вопросах установки стоит значение по умолчанию: Enter выбирает его. Для Micro рекомендуется 10.
- «Последний анализ» в статусе: анализ идёт раз в сутки (при старте службы и затем каждые 24 ч), это не время последнего всплеска. Сам анализ только считает план на сутки; всплески идут весь день по плану и в журнал не пишутся. Проверить всплеск: пункт 2 несколько раз (будет «всплеск идёт: да») или `pgrep -af "while :"`.
- Время в журнале и статусе берётся с часов сервера.
- Нагрузка по факту больше цели: каждый 3-минутный всплеск в расчёте считается как 2 минуты (запас), поэтому цель 10% даёт 72 всплеска, то есть около 3,6 ч нагрузки в сутки.
- Файл `keepalive.sh` можно удалить с сервера: служба, демон, конфиг и история остаются и продолжают работать. Новый скрипт читает их состояние (пункты 2, 3, 4, 5, 6 работают с уже установленной службой).
- Пункт 1 при повторном запуске не проверяет, что служба уже есть: останавливает её, перезаписывает демон, службу и конфиг и запускает заново; историю `state.json` не стирает. Целевой процент спросит заново (по умолчанию 30 для памяти и 10 для ЦП, не текущее значение). Чтобы изменить только процент, лучше пункт 5. Чтобы убрать защиту совсем, сначала пункт 6, потом удалять файл.
