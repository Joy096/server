# server_setup.sh: первичная настройка нового сервера (Ubuntu/Debian)

Запуск: `wget -O server_setup.sh https://raw.githubusercontent.com/Joy096/server/refs/heads/main/server_setup.sh && bash server_setup.sh` (после выхода файл сам себя удаляет: `trap ... rm -f "$SCRIPT_PATH"`). Описания в проекте раньше не было; добавлено 27.11.2026 при переносе автообновления. В тот же день скрипт переименован из `server_new.sh` в `server_setup.sh` (решение Vitalii); старая ссылка на `server_new.sh` больше не работает. Резервная копия под старым именем: `server_new.before_rename.sh`. Пункт 1 общего меню `main.sh`. В конце скрипт перезагружает сервер.

## Что делает (по порядку)
1. SSH-ключи: копирует `authorized_keys` пользователя, который запустил скрипт (в том числе через `sudo`), в `/root/.ssh`. От root или без файла ключей этот шаг пропускается.
2. Обновление системы без вопросов (`apt update/upgrade/autoremove` через `env DEBIAN_FRONTEND=noninteractive NEEDRESTART_MODE=a`), ставит `git`.
3. Останавливает и отключает `netfilter-persistent`, ставит `ufw`: входящие закрыты, исходящие открыты, разрешены реальные порты SSH (из текущего подключения, `sshd -T` и `ss`; если не нашлось, 22), 80 и 443.
4. BBR (`/etc/sysctl.d/99-bbr.conf`), локаль `ru_UA.UTF-8`, часовой пояс `Europe/Kyiv`.
5. Автообновление системы по ночам (см. ниже).
6. Ставит `aptitude` (при необходимости включает репозиторий `universe`), `aptitude upgrade -y`, перезагрузка.

## Автообновление (с 27.11.2026 без отдельного файла в репозитории)
- Скрипт создаётся прямо на сервере: `/usr/local/sbin/server-updater.sh` (права 755). Код тот же, что раньше был в `updater.sh`: `apt update`, `apt full-upgrade`, `autoremove`, пауза 120 с, удаление старых версий snap, `/sbin/reboot`. ⚠️ Каждую ночь перезагружает сервер.
- Cron пользователя root: `0 4 * * * /usr/local/sbin/server-updater.sh > '/root/updater.log' 2>&1`.
- Старая задача (она скачивала `updater.sh` с GitHub: в строке есть `.../main/updater.sh`) при запуске скрипта удаляется, чтобы обновление не шло дважды. Чужие задачи в crontab не трогаются. Стандартный заголовок crontab добавляется только в пустой crontab (раньше при повторном запуске он дублировался).
- Повторный запуск `server_setup.sh` безопасен для cron: дублей не будет, а старое задание заменится новым.
- **Перенос старых серверов:** пока на сервере старая задача, она работает только пока `updater.sh` лежит в GitHub. Чтобы перейти на новый вариант, нужно один раз запустить `server_setup.sh` заново (он целиком перенастраивает сервер и перезагружает его).
