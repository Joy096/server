# rustdesk.sh: свой сервер RustDesk (hbbs + hbbr)

Скрипт для сервера Oracle (Micro или Ampere): ставит сервер удалённого доступа RustDesk напрямую службами systemd, без Docker. Запуск: `sudo bash rustdesk.sh`. Интерфейс только на русском.

## Решения Vitalii (02.11.2026)
- Заменяет старый скрипт `rustdesk_manager.sh` (делал с Gemini, через Docker). Docker не нужен: на Micro он съедает 80-150 МБ памяти из ~950.
- Работает и на Micro (x86_64, файл `amd64`), и на Ampere (aarch64, файл `arm64v8`): тип определяется сам.
- Режим «только по ключу» (`-k _`): без ключа сервера никто не подключится.
- Ожидание ключа после запуска: до 30 секунд.
- Порты: ufw используется, поэтому при включённом ufw правила добавляются только через него; если ufw выключен, через iptables (вставка перед завершающим REJECT, сохранение через netfilter-persistent или /etc/iptables/rules.v4). Порты в консоли Oracle у Vitalii уже открыты, подсказок про консоль в скрипте нет.
- Автообновление включено по умолчанию (раз в неделю, воскресенье около 04:00 + случайная задержка до часа). Итог пишется только в журнал, в Telegram не отправляется (решение Vitalii).
- Определение IP: метаданные Oracle, затем ifconfig.me, api.ipify.org, icanhazip.com; если ничего не вышло, IP вводится вручную. Можно указать домен.

## Что и где лежит
- Программа: `/opt/rustdesk/hbbs`, `/opt/rustdesk/hbbr` (при обновлении копия предыдущей версии в `/opt/rustdesk.bak`)
- Ключи и база: `/var/lib/rustdesk` (пользователь `rustdesk`, права 700)
- Настройки: `/etc/rustdesk-server.conf` (`ADDR=` адрес для клиентов, `VERSION=` установленная версия); служба hbbs берёт адрес из этого файла
- Службы: `rustdesk-hbbs`, `rustdesk-hbbr`; обновление: `rustdesk-update.service` + `rustdesk-update.timer`
- Копия скрипта для автообновления: `/usr/local/sbin/rustdesk-manager.sh` (запускается с `--auto-update`; обновляется при каждом запуске меню, если автообновление включено)
- Журнал обновлений: `/var/log/rustdesk-update.log` (обрезается до последних 200 строк при размере больше 200 КБ)
- Порты: TCP 21115-21117, UDP 21116 (порты веб-клиента 21118/21119 не открываются)
- Службы работают от пользователя `rustdesk` и не затрагивают WireGuard и kill-switch TorrServer/qBittorrent (те заворачивают в VPN только трафик пользователя `torrserver`).

## Меню
1. Установить / переустановить (при повторном запуске спрашивает; ключ сохраняется; Enter = нет)
2. Данные для подключения (адрес и ключ + подсказка, куда вводить в клиенте)
3. Статус и журнал (версия, службы, память, порты, автообновление, последние записи журналов)
4. Перезапустить
5. Обновить сейчас
6. Автообновление: включить / выключить
7. Сменить адрес (IP или домен); ключ прежний
8. Удалить (подтверждение; про ключ спрашивает отдельно, Enter = нет, ключ остаётся)
9. Адресная книга и вход в аккаунт (API-сервер, по желанию Google): подменю, см. ниже
0. Выход

## Пункт 9: API-сервер (вход в аккаунт и общая адресная книга), добавлено 02.11.2026
Зачем: в бесплатном сервере RustDesk нет аккаунтов и адресной книги (это платный Server Pro). Клиент при указании своего сервера теряет прежний вход; кнопки Google и т.п. клиент берёт у «Сервера API». Решение Vitalii: поставить сторонний бесплатный `lejianwen/rustdesk-api` (Go, админка, вход паролем, по желанию Google/GitHub/OIDC), домен у Vitalii есть, кнопка Google желательна, но не обязательна.

- Ставится без Docker: релиз `linux-amd64.tar.gz` / `linux-arm64.tar.gz` с GitHub (`lejianwen/rustdesk-api`), в `/opt/rustdesk-api` (файл `apimain`, `conf/config.yaml`, `resources`, `data` с базой SQLite, `runtime` с журналом). Служба `rustdesk-api` от отдельного пользователя `rustdesk-api`.
- Настройки: `/etc/rustdesk-api.conf` (`API_DOMAIN`, `API_TLS`, `API_VERSION`, `NGINX_ADDED`) и `/etc/rustdesk-api.env` (переменные `RUSTDESK_API_*`: адреса ID/ретранслятора, ключ, адрес API, язык en, веб-клиент выключен). Адрес прослушивания также прописывается в `conf/config.yaml` (`api-addr`).
- Без HTTPS: программа слушает 0.0.0.0:21114 (пароль идёт открытым текстом, Google недоступен; скрипт предупреждает и просит подтвердить). С HTTPS: программа слушает 127.0.0.1:21124, перед ней nginx (служба `rustdesk-api-tls`, свой конфиг `/etc/rustdesk-api/nginx.conf`, стандартная служба nginx отключена) на порту 21114 с сертификатом из `/root/my_cert/<домен>/` (его делает `ssl.sh`, пункт 1). Раз в сутки таймер `rustdesk-api-tls-reload` перечитывает сертификат (чтобы продление подхватывалось без правки `ssl.sh`).
- Пакет nginx ставится с запретом автозапуска; при удалении убирается, только если его поставил этот скрипт и нет `/etc/jackett-cert/nginx.conf`.
- Порт 21114/tcp открывается так же, как порты сервера (ufw, если включён, иначе iptables).
- Регистрация посторонних выключена (так по умолчанию), пользователей создаёт админ.
- Пароль admin (решение Vitalii 03.11.2026): при установке скрипт предлагает ввести свой (минимум 8 символов, ввод дважды; при ошибке спрашивает заново), Enter = случайный (тогда показывается один раз). Задаётся через `apimain reset-admin-pwd`, нигде не хранится. Сменить позже: подменю пункт 4 (тот же вопрос).
- Домен (решение Vitalii 03.11.2026): определяется автоматически и подставляется по умолчанию (Enter): прежний домен из `/etc/rustdesk-api.conf`, иначе адрес сервера, если это домен с сертификатом в `/root/my_cert/<домен>/`, иначе самый новый сертификат `ssl.sh`. «-» = без домена. Вручную вводить не нужно.
- Язык админки: `RUSTDESK_API_LANG="en"` (язык сообщений программы; по документации поддерживаются только `en` и `zh-CN`, поэтому `ru` не ставится). Но сама веб-панель имеет переключатель языка (значок справа вверху) с русским: Vitalii подтвердил скриншотом 03.11.2026. Скрипт его не меняет, выбор делается в панели. (Ошибочное утверждение «русского нет» было поправлено в тексте скрипта.)
- Частая ошибка клиента (скриншот 03.11.2026): «Connection refused ... https://домен/api/login, порт 443» значит, что в поле «Сервер API» адрес вписан без порта. Нужно `https://домен:21114`; в подсказке скрипта это теперь сказано явно.
- Адресная книга не добавляет устройства сама: список заполняется вручную или пакетно из админки (раздел «Пиры» -> «Пакетное добавление в адресную книгу»). Авто-появление устройств одного аккаунта (вкладка группы/«доступные устройства», общая группа) в этой программе не подтверждено, нужно проверять на живом сервере.
- После установки вывод называется «Сервер API для настроек RustDesk» (так назвал Vitalii).
- Подменю: 1 установить/переустановить (база сохраняется), 2 данные для входа и инструкция Google (куда зайти и что нажать), 3 статус и журнал, 4 сменить пароль admin, 5 подключить HTTPS/сменить домен, 6 обновить сейчас (с откатом, если не запустилась), 7 удалить (базу удалять только по отдельному вопросу, Enter = оставить), 0 назад.
- Автообновления у API-сервера нет (сторонняя программа с логинами, обновляется только вручную пунктом 6).
- При смене адреса сервера (пункт 7 главного меню) и при переустановке сервера API получает новые адреса и ключ сам (`api_refresh`).
- Вход через Google настраивается в админке и в Google Cloud Console; callback `https://<домен>:21114/api/oidc/callback`. Сопоставление Google-аккаунта с пользователем зависит от версии программы и не проверялось.
- Не проверено на живом сервере: структура архива релиза (скрипт ищет `apimain` сам и требует `conf/config.yaml`), переменная `RUSTDESK_API_GIN_API_ADDR` (адрес дополнительно правится в `config.yaml`), расположение базы (предполагается `data/`).

## Как устроено обновление
Версия берётся с GitHub (`rustdesk/rustdesk-server`, последний релиз), файл `rustdesk-server-linux-<amd64|arm64v8>.zip`. Новая версия сначала скачивается и распаковывается во временную папку, потом файлы подменяются, службы перезапускаются и проверяются несколько секунд. Если службы не поднялись, возвращается прежняя версия из `/opt/rustdesk.bak`, запись об откате идёт в журнал. Параллельный запуск блокируется через flock.

## Перенос со старой установки через Docker
Если найден `/opt/rustdesk-server/data/id_ed25519(.pub)`, при установке предлагается забрать ключ (Enter = да), чтобы клиентам ничего не менять. Работающие контейнеры `hbbs`/`hbbr` предлагается остановить и отключить автозапуск (Enter = да). Старая папка не удаляется.

## Проверки
`bash -n` проходит. Тест на заглушках (systemctl, curl, ufw, iptables, docker, nginx, runuser, пути): установка, данные, статус, автообновление вкл/выкл, смена адреса, обновление, откат при неудачной версии, перенос ключа, путь через iptables, удаление с сохранением ключа; для API-сервера: установка с HTTPS и без, включение HTTPS позже, смена пароля, обновление и откат, удаление с базой и без. Настоящего сервера в песочнице нет, поэтому живую установку на Oracle ещё не проверяли.

Резервные копии (только в рабочей папке, в проект не записывались): `rustdesk.before_api.sh` (до API-сервера), `rustdesk.before_adminpw.sh` (до правок про пароль, домен и название).
