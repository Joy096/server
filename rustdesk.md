# rustdesk.sh: свой сервер RustDesk (hbbs + hbbr)

Скрипт для сервера Oracle (Micro или Ampere): ставит сервер удалённого доступа RustDesk напрямую службами systemd, без Docker. Запуск: `sudo bash rustdesk.sh`. Интерфейс только на русском.

## Решения Vitalii (02.11.2026)
- Заменяет старый скрипт `rustdesk_manager.sh` (делал с Gemini, через Docker). Docker не нужен: на Micro он съедает 80-150 МБ памяти из ~950.
- Работает и на Micro (x86_64, файл `amd64`), и на Ampere (aarch64, файл `arm64v8`): тип определяется сам.
- Режим «только по ключу» (`-k _`): без ключа сервера никто не подключится.
- Ожидание ключа после запуска: до 30 секунд.
- Порты: ufw используется, поэтому при включённом ufw правила добавляются только через него; если ufw выключен, через iptables (вставка перед завершающим REJECT, сохранение через netfilter-persistent или /etc/iptables/rules.v4). Порты в консоли Oracle у Vitalii уже открыты, подсказок про консоль в скрипте нет.
- Автообновление включено по умолчанию (раз в неделю, воскресенье около 04:00 + случайная задержка до часа). Итог пишется только в журнал, в Telegram не отправляется (решение Vitalii).
- Определение IP: метаданные Oracle, затем ifconfig.me, api.ipify.org, icanhazip.com; если ничего не вышло, IP вводится вручную. Можно указать домен.

## Что и где лежит
- Программа: `/opt/rustdesk/hbbs`, `/opt/rustdesk/hbbr` (при обновлении копия предыдущей версии в `/opt/rustdesk.bak`)
- Ключи и база: `/var/lib/rustdesk` (пользователь `rustdesk`, права 700)
- Настройки: `/etc/rustdesk-server.conf` (`ADDR=` адрес для клиентов, `VERSION=` установленная версия); служба hbbs берёт адрес из этого файла
- Службы: `rustdesk-hbbs`, `rustdesk-hbbr`; обновление: `rustdesk-update.service` + `rustdesk-update.timer`
- Копия скрипта для автообновления: `/usr/local/sbin/rustdesk-manager.sh` (запускается с `--auto-update`; обновляется при каждом запуске меню, если автообновление включено)
- Журнал обновлений: `/var/log/rustdesk-update.log` (обрезается до последних 200 строк при размере больше 200 КБ)
- Порты: TCP 21115-21117, UDP 21116 (порты веб-клиента 21118/21119 не открываются)
- Службы работают от пользователя `rustdesk` и не затрагивают WireGuard и kill-switch TorrServer/qBittorrent (те заворачивают в VPN только трафик пользователя `torrserver`).

## Меню
1. Установить / переустановить (при повторном запуске спрашивает; ключ сохраняется; Enter = нет)
2. Данные для подключения (адрес и ключ + подсказка, куда вводить в клиенте)
3. Статус и журнал (версия, службы, память, порты, автообновление, последние записи журналов)
4. Перезапустить
5. Обновить сейчас
6. Автообновление: включить / выключить
7. Сменить адрес (IP или домен); ключ прежний
8. Удалить (подтверждение; про ключ спрашивает отдельно, Enter = нет, ключ остаётся)
0. Выход

## Как устроено обновление
Версия берётся с GitHub (`rustdesk/rustdesk-server`, последний релиз), файл `rustdesk-server-linux-<amd64|arm64v8>.zip`. Новая версия сначала скачивается и распаковывается во временную папку, потом файлы подменяются, службы перезапускаются и проверяются несколько секунд. Если службы не поднялись, возвращается прежняя версия из `/opt/rustdesk.bak`, запись об откате идёт в журнал. Параллельный запуск блокируется через flock.

## Перенос со старой установки через Docker
Если найден `/opt/rustdesk-server/data/id_ed25519(.pub)`, при установке предлагается забрать ключ (Enter = да), чтобы клиентам ничего не менять. Работающие контейнеры `hbbs`/`hbbr` предлагается остановить и отключить автозапуск (Enter = да). Старая папка не удаляется.

## Проверки
`bash -n` проходит. Тест на заглушках (systemctl, curl, ufw, iptables, docker, пути): установка, данные, статус, автообновление вкл/выкл, смена адреса, обновление, откат при неудачной версии, перенос ключа, путь через iptables, удаление с сохранением ключа. Настоящего сервера в песочнице нет, поэтому живую установку на Oracle ещё не проверяли.
