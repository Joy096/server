# oracle.sh (до 27.10.2026 назывался oracle_arm_full.sh) — полное описание скрипта

Интерактивный bash-скрипт для Ubuntu-сервера, который автоматически создаёт сервер Oracle Cloud (Always Free) в фоне, пока не появится свободное место, и позволяет управлять серверами аккаунта без захода в консоль Oracle. Запуск: `sudo bash oracle.sh` (на любом сервере, работающем круглосуточно, не обязательно на Oracle).

Стиль проекта: файл скрипта автопоиска называется `oracle.sh` (решение Vitalii от 27.10.2026), весь текст интерфейса на русском, пояснения подробные и понятные новичку. Версия на момент записи: 1321 строка, `bash -n` проходит.

---

## 1. Что умеет

1. Ставит консольную утилиту Oracle (OCI CLI) в отдельное venv `/opt/oci-cli`.
2. Помогает подключить аккаунт: создаёт API-ключ, показывает публичный ключ и инструкцию, куда его вставить в консоли, проверяет доступ.
3. Мастер создания сервера повторяет мастер консоли «Создать экземпляр» (те же названия шагов): Базовая информация → Образ и шаблон конфигурации → Безопасность → Сети (ключи SSH) → Хранилище.
4. Фоновая служба systemd `oracle-arm-retry` раз в несколько минут пробует создать сервер по всем доменам доступности, пока не получится.
5. Уведомления в Telegram (мастер из 3 шагов с подробной инструкцией и тестовым сообщением).
6. «Мои серверы»: список серверов и их характеристик, остаток лимита Always Free, изменение ЦП/памяти (Ampere), увеличение диска, удаление.
7. Ручное создание ещё одного сервера параллельно с фоновым поиском.
8. Полное удаление всего, что поставил скрипт.

---

## 2. Меню (текущая структура)

Шапка с **строкой состояния**:
- `Аккаунт Oracle:` подключён (регион …) / не подключён
- `Автопоиск:` не настроен / остановлен (Ampere N ЦП / M ГБ или Micro) / работает (…) / сервер создан ✅ (…)
- `Следующий шаг:` подсказка, что нажать дальше

Главное меню:
1. **Подключение к Oracle** (утилита и аккаунт) = `connect_oracle` (`configure_oci` + обновление статуса)
2. **Автопоиск места** (подменю `search_menu`):
   1. Настройка параметров поиска (`setup_task`)
   2. Запустить поиск / Остановить поиск (надпись зависит от состояния службы)
   3. Статус и журнал (`show_status`)
   0. Назад
3. **Мои серверы** (подменю `servers_menu`):
   1. Список и управление (`manage_servers`)
   2. Создать сервер вручную (`setup_task manual`)
   0. Назад
4. **Удаление скрипта** и всего, что он поставил (`uninstall_all`)
0. Выход

**Мастер первого запуска** (`first_run_wizard`): если аккаунт не подключён и нет файла настроек, предлагает пройти по шагам: подключение → что искать → запуск поиска.

Решения по меню, принятые Vitalii:
- «Пробная попытка» (`try_once`) удалена навсегда: скрипт и так пробует, а если не получится, говорит об этом.
- Сообщение «Утилита oci уже установлена.» выводится только в пункте «Статус» (строка «Утилита oci: установлена»), в других местах молчим.
- В строке состояния нет номера последней попытки.
- В статусе автопоиска показывается выбранный вариант (Ampere N ЦП / M ГБ или Micro).
- В конце настройки: «Запустить поиск в фоне сейчас? [Y/n]»; после запуска строки «Журнал: …» нет.
- Если фоновый поиск уже работает, а настройки изменили, скрипт сам перезапускает службу и говорит об этом.

## 3. Константы и файлы

| Что | Путь / значение |
|---|---|
| venv утилиты | `OCI_VENV=/opt/oci-cli`, `OCI_BIN=$OCI_VENV/bin/oci`, ссылка `OCI_LINK=/usr/local/bin/oci` |
| конфиг OCI | `OCI_CFG=/root/.oci/config` (ключи `~/.oci`, скриптом НЕ удаляются) |
| настройки поиска | `CONF_FILE=/etc/oracle-arm.conf` (chmod 600) |
| копия SSH-ключа для сервера | `KEY_COPY=/etc/oracle-arm-ssh.pub` |
| состояние скрипта (что установил) | `STATE_FILE=/etc/oracle-arm.state` (`OCI_INSTALLED`, `PKGS_ADDED`) |
| служба | `SVC=oracle-arm-retry`, `UNIT=/etc/systemd/system/oracle-arm-retry.service` |
| рабочий скрипт службы | `WORKER=/usr/local/sbin/oracle-arm-worker.sh` (генерируется функцией `install_worker`) |
| журнал | `LOG=/var/log/oracle-arm.log` (ротация: >2 МБ → последние 500 строк) |
| признак «сервер создан» | `DONE_FILE=/var/lib/oracle-arm.done` |

Переменные в `/etc/oracle-arm.conf`: `REGION, TENANCY, COMPARTMENT, ADS, SHAPE, SUBNET_ID, SUBNET_NAME, ASSIGN_IP, IMAGE_ID, IMAGE_NAME, OCPU, MEM, BOOT, IN_TRANSIT, NAME, KEYFILE, SSH_MODE, INTERVAL, TG_TOKEN, TG_CHAT`.

Рабочий скрипт — это **сгенерированная копия** (heredoc в `install_worker`, пишется в `WORKER.new` и атомарно `mv`). Служба запускает её, а не `oracle.sh`. Поэтому после замены основного файла служба продолжает работать со старым кодом и теми же настройками; чтобы взять новый код, нужно «Остановить поиск» → «Запустить поиск» (`start_retry` всегда вызывает `install_worker` заново).

## 4. Мастер создания (`setup_task [manual]`)

Порядок вопросов (названия как в консоли Oracle):
- Подключение к аккаунту проверяется (`oci_check`), иначе «Сначала подключите аккаунт Oracle (пункт 1)».
- Регион и домены доступности (AD) берутся из аккаунта; скрипт пробует все AD по очереди. Предупреждение: Always Free создаётся только в домашнем регионе.
- **1. Базовая информация:** имя (по умолчанию `instance-ГГГГММДД-ЧЧММ`, только `A-Za-z0-9_-`).
- **2. Образ и шаблон конфигурации:**
  - Конфигурация: только **Always Free** — `VM.Standard.A1.Flex` (Ampere) или `VM.Standard.E2.1.Micro`. Список «Конфигурация (🏷 Режим «Всегда бесплатно» применим)».
  - Ampere: ЦП 1–остаток лимита (по умолчанию весь остаток), память ГБ (по умолчанию 6×ЦП, не больше остатка). Лимит считается по уже созданным серверам (`used_resources`).
  - Micro: 1 ЦП, 1 ГБ, изменить нельзя; максимум 2 сервера.
  - Образ: **только Canonical Ubuntu**, из каждой версии самый новый образ (`group_by` по версии, `max_by time-created`), названия короткие («Canonical Ubuntu 24.04» и т.п.), «(новейшая)» у первой, «(рекомендую: на ней проверены мои скрипты)» у 24.04 — она по умолчанию. Дополнительная информация об образах убрана по просьбе Vitalii.
- **3. Безопасность:** защищённые экземпляры (Shielded) НЕ реализованы, потому что на A1.Flex не поддерживаются; шифрование «при передаче» (`--is-pv-encryption-in-transit-enabled`) спрашивается.
- **4. Сети:** выбор подсети (публичная нужна для внешнего IP; если выбрана приватная — предупреждение и «Всё равно продолжить? [y/N]»); «Автоматически назначить общедоступный IPv4-адрес? [Y/n]»; **Добавить ключи SSH** — 4 способа: создать пару для меня, загрузить файл `.pub`, вставить открытый ключ, не добавлять ключ. Закрытый ключ можно показать на экране (по y/n).
- **5. Хранилище:** загрузочный том по умолчанию около 47 ГБ; пользовательский размер спрашивается отдельно («Указать размер пользовательского загрузочного тома? [y/N]»), тогда 50–200 ГБ (по умолчанию предлагается весь свободный остаток лимита 200 ГБ), шифрование.
- **Telegram** (необязательно, `setup_telegram`): 3 шага (создать бота в @BotFather → написать боту Start → ввод токена; chat_id находится автоматически) + тестовое сообщение. Если бот уже настроен, предлагается оставить (повторно вводить не нужно). При ошибке отправки уведомления выключаются, подсказка повторить настройку.
- Интервал между попытками **больше не спрашивается**: в скрипте написано, как это работает (INTERVAL=180 с + случайные 0–30 с между кругами; плюс пауза между доменами AD_PAUSE=60 с + случайные 0–14 с, см. раздел 5).
- Сохранение в `CONF_FILE`, генерация рабочего скрипта, показ плана `show_plan`, затем «Запустить поиск в фоне сейчас? [Y/n]» (или автоперезапуск, если уже работает).

Режим `manual` (пункт «Создать сервер вручную»): те же вопросы, но настройки в `CONF_FILE` не сохраняются и фоновая служба не затрагивается. Предупреждает, если имя совпадает с именем фонового поиска. После вопросов `manual_launch`: «Пробовать создать сейчас? [Y/n]», «Повторять в этом окне до успеха? [y/N]» (повтор каждые 3 минуты в окне терминала, Ctrl+C останавливает; trap на INT), уведомление в Telegram берётся из `CONF_FILE`.

## 5. Поведение рабочего скрипта (служба)

Цикл:
1. `exists_already`: если сервер с таким именем уже есть (не TERMINATED/TERMINATING) — `finish 0` («уже существует»), служба выключается.
2. По каждому AD (перед вторым и третьим AD пауза `AD_PAUSE=60` с + случайные 0–14 с; константа в рабочем скрипте, в `CONF_FILE` не хранится, в режиме `ONCE=1` паузы нет): `oci compute instance launch` с параметрами из конфига (`--shape-config` для `.Flex`, `--ssh-authorized-keys-file`, `--boot-volume-size-in-gbs`, `--assign-public-ip`, `--is-pv-encryption-in-transit-enabled`).
3. Разбор ответа:
   - успех → ждёт внешний IP до 5 минут (`public_ip`), `finish 0` с сообщением и Telegram, создаётся `DONE_FILE`;
   - `Out of host capacity` → запись «попытка N, AD: нет места» и следующий AD;
   - `TooManyRequests / 429` → пауза 10 минут;
   - `LimitExceeded` → считается по каждому AD отдельно (лимит у Micro может быть по доменам); служба останавливается (`finish 3`) только если лимит сработал во ВСЕХ AD подряд; в журнал пишется сообщение Oracle;
   - `NotAuthenticated / 401 / NotAuthorizedOrNotFound / 404` → `finish 4` («Проверьте подключение (пункт 1) и настройки поиска (пункт 2)»);
   - прочее → «неизвестная ошибка (k/10)»; 10 подряд → `finish 5`.
4. Пауза `INTERVAL + случайные 0–30 с`.
5. `finish`: пишет в журнал, шлёт Telegram, `systemctl disable` службы (чтобы после перезагрузки сервера не стартовала), при успехе создаёт `DONE_FILE`.

Служба: `Restart=no`, `WantedBy=multi-user.target`, включена (`enable --now`), поэтому **переживает перезагрузки** (в том числе ежедневные) и сама отключается при успехе или фатальной ошибке.

Время цикла: внутри `oci` есть собственные повторы, поэтому один вызов `launch` занимает ~100 секунд. Три AD ≈ 5 минут + две паузы между доменами ≈ 2 минуты + пауза между кругами ≈ 3 минуты ≈ 10–11 минут на полный круг по трём доменам (до 27.10.2026 было 8–8,5 минут, без пауз между доменами). Если приходит 429, остаток круга пропускается, пауза 10 минут, затем новый круг. Запись журнала «попытка N» = один целый круг по доменам. Vitalii это известно, предложение добавить `--no-retry` (запросов в 2–3 раза меньше, круг ≈ 3 минуты) он обсудил и **решил ничего не менять**: «меня устраивает то что есть сейчас».

## 6. «Мои серверы»

- `load_servers`: читает `compute instance list`, VNIC (внешний IP), загрузочные тома → массивы `SRV_*`.
- `print_servers`: список (имя, тип, ЦП/память, диск, IP, статус). ЦП показывается без «.0» (`${cpu%.0}`).
- `print_limits`: «Ampere: X из 4 ЦП, Y из 24 ГБ; Micro: N из 2; Диски: Z из 200 ГБ».
- Для выбранного сервера:
  1. **Изменить ЦП и память** (только Ampere): `oci compute instance update --shape-config … --update-operation-constraint ALLOW_DOWNTIME --force`; максимум = лимит минус то, что заняли другие Ampere; предупреждение о возможной перезагрузке 1–3 мин.
  2. **Увеличить диск:** `oci bv boot-volume update --size-in-gbs … --force`; только увеличение; после этого перезагрузка, проверка `df -h /`.
  3. **Удалить:** `compute instance terminate --preserve-boot-volume <true|false> --force`, подтверждение вводом имени сервера; вопрос про удаление/сохранение диска.

## 7. Удаление (`uninstall_all`)

Показывает, что найдено (служба и скрипт, настройки/копия ключа/журнал, утилита `oci`, пакеты, поставленные скриптом), спрашивает подтверждение, удаляет. Пакеты, которые поставил скрипт (`python3 python3-venv jq curl openssh-client`), учитываются в `PKGS_ADDED` (`apt_install_tracked`) и удаляются только по отдельному подтверждению. Ключ `~/.oci` не удаляется.

## 8. Технические приёмы (важно для правок)

- Ввод пользователя внутри функций, где stdin занят, — через fd 3: `exec 3<&0`, `read -u 3`.
- Помощники: `pick_from` (результат в `PICKED` / `PICKED_IDX`), `ask_number`, `yn_d "Вопрос" y|n` (Enter = значение по умолчанию, в подсказке показывается Y/n или y/N — по просьбе Vitalii у вопросов с Enter всегда указано, к какому ответу относится Enter), `yn`.
- Все `read` в циклах заканчиваются `|| return 1`, чтобы не зависать на EOF.
- `export SUPPRESS_LABEL_WARNING=True` (предупреждение OCI о метке ключа не считается ошибкой); `verify_access` судит по коду возврата, а не по stderr.
- `write_oci_config` создаёт ключи с уникальными именами (по времени) и показывает публичный ключ из `key_file`, указанного в конфиге (был баг: показывался не тот ключ → несовпадение fingerprint).
- Статус аккаунта кэшируется в `ACCT_OK` (иначе строка состояния каждый раз делала бы сетевой запрос); обновляется `refresh_acct` после подключения.
- Рабочий скрипт обновляется атомарно (`mv`), служба при этом не ломается.
- Проверка перед выдачей: `bash -n`, плюс тесты на заглушках (см. раздел 9).

## 9. Как тестировали (без настоящего Oracle)

Тестовая среда в scratchpad: путь из файла `ora_path`, там `base.sh` (скрипт до маркера «МЕНЮ» с подменой путей через `sed`), `lib.sh` с функцией `run()` (подаёт ввод, вырезает цвета), заглушки `opt-oci/bin/oci`, `bin/systemctl` (состояние службы по файлу `/tmp/svc_on`), `bin/curl`, `bin/ssh-keygen`, `images.json`, `instances.json`, каталоги `etc/`, `sysd/`. Реальный `oci-cli` в venv `ocicli/` использовался только для проверки флагов (`--no-retry` — глобальный флаг; `--update-operation-constraint ALLOW_DOWNTIME`; `--preserve-boot-volume`). Тестируются: меню и подменю, строка состояния для состояний «не настроен/остановлен/работает/создан», мастер первого запуска, вопрос «Запустить поиск сейчас?», сценарии ошибок (нет места, 429, LimitExceeded, 401, неизвестная).

На настоящем Oracle скрипт работает у Vitalii (проверено им: поиск, создание Micro вручную, список серверов).

## 10. История решений и отказов (чтобы не предлагать заново)

- Ubuntu only; конфигурации только Always Free (Ampere с настраиваемыми ЦП/памятью в пределах лимита + Micro).
- Telegram: шаги 1–3 объединены в один мастер; в конце тест.
- Интервал сначала спрашивался в секундах → в минутах → **вопрос убран**, работает автоматом.
- Профили поиска (несколько вариантов сервера одновременно, перебор по кругу): реализовывались (`oracle_arm_full.with_profiles.sh`), затем **Vitalii передумал, откат**. Фоновый поиск — только одна задача; для второго сервера есть ручной режим.
- Пункты меню: «Параметры» при изменении перезапускают службу сами; ручное создание — отдельно и независимо от фона.
- Пробная попытка удалена; добавлены строка состояния, «Следующий шаг», мастер первого запуска.
- `--no-retry` обсуждали, не внедряли.
- Shielded Instance на Ampere не реализуется (не поддерживается).
- 27.10.2026: сообщения «429, Oracle просит притормозить» стали частыми, Vitalii попросил увеличить промежутки между запросами к разным доменам (бывало ~1,5 минуты). Сделано: пауза `AD_PAUSE=60` с (+0–14 с) между доменами в рабочем скрипте; `INTERVAL` между кругами не менялся. Тексты «раз в 8 минут» заменены на «10–11 минут».
- Баги, исправленные по ходу: показ неверного публичного ключа; stderr-предупреждения как ошибка; зависание на EOF; «103 ГБ103»; ocpus «1.0»; `LimitExceeded` останавливал поиск при первом домене (теперь только если во всех); ручной режим Micro упирался в лимит одного AD.

## 11. Резервные копии версий (в рабочей папке)

`oracle_arm_full.before_wizard.sh`, `…before_micro.sh`, `…before_profiles.sh`, `…with_profiles.sh`, `…before_menu.sh`, `…before_adpause.sh` (перед паузой между доменами, 27.10.2026) — предыдущие этапы.
